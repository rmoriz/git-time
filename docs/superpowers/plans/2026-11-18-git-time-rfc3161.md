# git-time (RFC 3161 commit sealing) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seal every git commit with independently verifiable RFC 3161 timestamp tokens from several TSAs in parallel, stored inside the commit object.

**Architecture:** A `post-commit` hook runs `git time hook post-commit`, which reads the new commit object, strips the previous trailer block and any signature to form the message imprint, queries all configured TSAs concurrently, verifies each response locally, re-composes the object byte-exactly (headers verbatim, trailer appended), re-signs it if it was signed, writes it with `git hash-object` and moves the ref with a compare-and-swap `git update-ref`. No amend, no daemon, no notes by default.

**Tech Stack:** Rust 2024 (MSRV 1.88), `clap`, `tokio`, `reqwest`+rustls, `sigstore-tsa` (RFC 3161 build/verify over `cms`/`x509-cert`/`webpki`), `sha2`, `zstd`, `base64`, `serde`, `jiff`, `rand`, `thiserror`. No OpenSSL at runtime.

**Spec:** `docs/superpowers/specs/2026-11-18-git-time-rfc3161-design.md` (read it before Task 1; §5 and §15 list the measured constraints).

## Global Constraints

- Trailer prefix is exactly `X-RFC3161-`, fields in this order: `Imprint`, `Object`, `Token`…, `Fail`….
- Token payload: zstd level 19, base64url **unpadded**, one token per `Token` line, `ver=1` first field.
- Signature covers the object **including** the trailer block; the imprint excludes trailer block **and** `gpgsig*` headers with their continuation lines.
- Never call `git commit --amend`. Never use `git commit-tree` for the rewrite.
- Compose changes only through `git hash-object -w -t commit --stdin`; move refs only through `git update-ref -m "rfc3161 seal" <ref> <new> <old>`.
- Assert strip(composed) == sealed pre-image before any ref move; abort the seal otherwise.
- Defaults: `time.required=1`, `time.deadline=10s`, `time.on-failure=warn`, `time.max-trailer-bytes=65536`, `time.seal-during-rebase=all`, `time.record-failures=true`.
- Verification is fail-closed (no anchors ⇒ `UNTRUSTED`, never PASS). Exit codes: 0 ok, 1 evidence problem, 2 usage.
- Hook must always exit 0 unless `on-failure=fail` (then 3); it must never touch the index or worktree.
- Full tool output goes to stderr; stdout is reserved for `log`/`verify --json`.
- Signed commits: re-sign with the key taken from the existing signature; re-sign failure aborts the seal with the original commit untouched.
- Support `gpg.format=openpgp` and `ssh`; honour `core.hooksPath`; POSIX `sh` shims only.

## Review Focus

1. Merge commit of a signed tag (`mergetag` header) — header must survive the rewrite and the `Object`/imprint must still reproduce.
2. `git commit --no-gpg-sign` while `commit.gpgSign=true` — the commit must stay unsigned.
3. Message shapes: empty message, trailing blank lines, trailing whitespace, CRLF, non-UTF-8 with `encoding` header — the recomputed imprint must equal the sealed one.
4. TSA answering HTTP 200 with `status=failure`, or a token with the wrong imprint/nonce — that TSA is recorded as failed, the commit is still sealed by the remaining quorum.
5. HEAD moving between capture and CAS (two commits in quick succession) — retry at most 3 times, else abort with the `git time seal` hint and leave the other commit intact.
