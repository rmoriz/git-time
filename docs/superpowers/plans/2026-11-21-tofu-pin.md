# Confirmable Trust-On-First-Use Pin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an expected fingerprint be stored before a custom authority is pinned, mark a pin that had none, have `doctor` keep naming it, and add `anchor confirm` as the place the out-of-band comparison is recorded.

**Architecture:** One optional config key joins the expectation list `accept::apply` already checks, so a first pin becomes a comparison instead of TOFU. A second key records the TOFU case, is cleared only by a real confirmation, and is read by `doctor` and by the seal warning.

**Tech Stack:** Rust 2024, `clap`, git config through the existing `local_set`/`local_get` helpers, the existing `accept::Applied` outcomes.

**Spec:** `docs/superpowers/specs/2026-11-21-tofu-pin-design.md`

## Global Constraints

- The expectation key is `time.tsa.<id>.fingerprint`, uppercase colon-separated hex, 20 or 32 octets, the spelling the preset table uses.
- The marker is `time.tsa.<id>.tofu = true`; it is **not** a policy input, so `verify` and the block format are untouched.
- Only `anchor fetch` can TOFU: `install` and `preset add` always have a publication, and `restore` cannot pin a custom id at all. The marker is therefore written and cleared in that one path.
- A marked pin verifies exactly like any other; nothing about trust changes.
- `cargo fmt` and `cargo clippy --all-targets -- -D warnings` clean before every commit.
- Commit messages say why; no `Co-Authored-By` trailer.
- The Picker's existing `tofu` word is the vocabulary; do not invent a second one.

## Review Focus

- `--accept` and a configured value that disagree: the explicit accept wins for that run, and the configured value is not overwritten.
- A fetch that matches only the root already pinned: stability is not confirmation, so the marker stays.
- `tsa add --fingerprint` on an id that already exists: the existing refusal stands and no key is written.
- `confirm` on an id with no bundle, or with a value the bundle does not carry: exit `1`, marker untouched.
- A hand-edited value that is not a fingerprint: the fetch refuses with the key named instead of comparing garbage.

**Interfaces:**
- Produces: `pub(crate) fn validate_fingerprint(fingerprint: &str) -> Result<String, String>` in `tsa.rs` — returns the value upper-cased, or the reason.
- Produces: `accept::apply(id, path, bytes, published, named, configured: Option<&str>, accept, tofu)` — the new parameter sits after `named`.
- Produces: the `time.tsa.<id>.fingerprint` key, written by `tsa add --fingerprint`.

- [ ] **Step 1: Write the failing tests**

`accept.rs` unit test: a served root matching `configured` pins without `accept` and is `Replaced`/`Appended` as the pinned case allows, while a different served root is `Mismatch` with the configured value named as `expected`.

`registry.rs`: `taa add <url> --id acme --fingerprint <fp> --insecure-http` writes `time.tsa.acme.fingerprint` upper-cased; `taa add ... --fingerprint dead:beef` exits `2` and writes nothing; a second `taa add` on the same id still refuses.

`install.rs` or `registry.rs`: with the key set and a stub serving a different root, `anchor fetch` exits `1`, names both values, and leaves the marker key out.

- [ ] **Step 2: Run them to make sure they fail**

Run: `cargo test -p git-time-cli fingerprint`
Expected: FAIL — the flag does not exist.

- [ ] **Step 3: Implement**

`validate_fingerprint`: split on `:`, require 20 or 32 two-digit uppercase-hexable parts after upper-casing, return the upper-cased value.

`taa add`: an `--fingerprint` flag, validated before anything is written, written as `fingerprint` in the fields list.

`apply`: the `configured` parameter joins the expectation list for matching and for `display`, ordered after `named` and after `published` and before the pinned roots; `accept` still overrides.

`anchor fetch`: read the key with `repo.config_non_empty`, pass it, and refuse with `Exit::config` when `validate_fingerprint` rejects it, naming the key. Pass `None` from `install_anchor`, `preset_add` and `restore`.

- [ ] **Step 4: Run the suite**

Run: `cargo test -p git-time-cli`
Expected: PASS.

- [ ] **Step 5: Commit**

```bash
git add -A
git commit -m "anchor: let tsa add store an expected fingerprint

A custom authority publishes nothing, so its first pin is whatever the
network returns. The value joins the expectation list the pin already
checks, which turns that first pin into a comparison. It is stored by
add and checked by the next fetch, because add fetches nothing."
```

### Task 2: The marker, and the verb that clears it

**Files:**
- Modify: `crates/git-time-cli/src/cmd/anchor.rs:44-72` (command), `:78-96` (dispatch), `:100-260` (`fetch`), new `confirm`
- Test: `crates/git-time-cli/tests/registry.rs`

**Interfaces:**
- Consumes: `validate_fingerprint` and the configured expectation from Task 1.
- Produces: `time.tsa.<id>.tofu = true`, set on `Applied::FirstPin { accepted: false }`, cleared when `matched.is_some()` or `accepted`; and `git time anchor confirm <id> [<fingerprint>]`.

- [ ] **Step 1: Write the failing tests**

TOFU via `anchor fetch` writes `tofu = true`; a re-fetch of the same root leaves it; a fetch that matches a configured value clears it; an `--accept` clears it.

`confirm` on a marked id clears the key and prints the confirmed root; with a value the bundle does not carry it exits `1` and the key stays; on an unmarked id it says so and exits `0`.

- [ ] **Step 2: Run them to make sure they fail**

Run: `cargo test -p git-time-cli --test registry tofu`
Expected: FAIL — no `time.tsa.*.tofu` is ever written.

- [ ] **Step 3: Implement**

In `fetch`, after `apply` returns, set or unset the marker per the Produces block; the `FirstPin { accepted: false }` arm additionally prints `git time anchor confirm <id> <fingerprint>` in its advice line. There is no unset helper yet: add `local_unset(repo, key)` beside `local_set` in `tsa.rs`, on `git config --local --unset`, tolerating git's exit `5` for a key that is not there.

`confirm(id, fingerprint)`: resolve the bundle with `anchors::target`, read its roots with `anchors::roots`; with a value, fail unless a root matches in the value's digest length (`accept::matches`); otherwise confirm the first root. Print every root it confirmed, unset the key.

- [ ] **Step 4: Run the suite**

Run: `cargo test -p git-time-cli`
Expected: PASS.

- [ ] **Step 5: Commit**

```bash
git add -A
git commit -m "anchor: mark a trust-on-first-use pin until someone confirms it

The printed fingerprint used to be the only review a first pin got, and
nothing afterwards said one was ever unconfirmed. The marker records it
and anchor confirm is where the out-of-band comparison is written down."
```
